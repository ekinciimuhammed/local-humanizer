# Local writing skills and open-source integrations

User requests research of GitHub humanizers, integration of their useful approaches, and usable skill support. Implement within the existing local app; no global Codex configuration changes. Prior authorization to make technical decisions and implement without repeated approval remains in effect.

## Selected design

- Bundle four compact, standalone SKILL.md writing profiles: Natural writing (blader/humanizer), Structure & clarity (andreaskonopka/humanizer), Voice & rhythm (harshaneel/humanize), Turkish clarity (original local adaptation). Preserve MIT notices, immutable upstream commit and SHA-256 for downloaded source files. Keep reviewed upstream texts as offline reference material, never load them automatically into the prompt.
- Default-enable Natural writing and Turkish clarity. A skill is a text-only editing guide, not executable code. All profiles must respect core preservation, source language, point of view, attribution, uncertainty, Markdown, and exact placeholders. No artificial errors, invented anecdotes, detector scoring or extra network calls.
- Settings → Skills lists description, origin/license, state and View/Download actions. Support local .md upload, preview before importing, custom instructions, enable/disable and delete custom profiles. No GitHub URL fetcher or code execution. Custom profiles persist in the existing encrypted-key settings file and survive Docker restarts. Skill text itself is not encrypted; no text histories or writing samples are added.
- Parse standard frontmatter name/description with plain, quoted and block scalars; ignore unrelated metadata as data, reject missing/oversized fields. Max 32 KiB per file, 12 custom skills, 3 enabled profiles, combined 24,000 instruction characters. Explicitly surface budget errors. Built-ins cannot be overwritten by custom imports. Imported skills start disabled.
- Send active instructions in the same single rewrite request, separated from immutable system rules. The complete final output must still pass deterministic checks. Prompts do not claim skills can override system instructions or run tools. Snapshot the enabled profiles at the start of a rewrite so settings changes cannot alter later chunks mid-document.
- Add small, collapsed Writing notes below a completed output: deterministic before/after counts for stock transitions, boilerplate, repetitive openings and rhythm. This is an editorial aid, never an AI/authorship detector or probability. Exclude immutable content from counts. No additional model calls.
- Preserve existing connections, credentials, generation settings and model selection during migration. No test writes or rewrites against the user's configured LLM. Validate with loopback mock server and offline Chromium in temporary data directories; rebuild existing Docker app only after checks pass.
